# 集成学习方法对比：RandomForest vs GBDT vs XGBoost

**阶段2.5 第二课** —— 2026-08-06

## 实验目标

对比三种集成学习方法在同一数据集上的表现：
- **RandomForest**（Bagging，并行投票）
- **GBDT**（Boosting，串行修正残差）
- **XGBoost**（GBDT + 正则化 + 二阶导数 + 并行化）

## 实验结果

| 模型 | 训练准确率 | 测试准确率 | 过拟合程度 | 训练时间(s) |
|------|-----------|-----------|----------|------------|
| **RandomForest** | 100.00% | 100.00% | 0.00% | 0.1083 |
| **GBDT** | 100.00% | 100.00% | 0.00% | 0.2717 |
| **XGBoost** | 100.00% | 100.00% | 0.00% | 0.1308 |

**数据集：** Iris（鸢尾花，150样本，4特征，3类）  
**参数配置：** n_estimators=100, learning_rate=0.1

## 核心洞察

### 1. Bagging vs Boosting 的本质差异

| 维度 | Bagging（随机森林） | Boosting（GBDT/XGBoost） |
|------|-------------------|------------------------|
| **训练方式** | 并行独立训练100棵树 | 串行训练，后树修正前树残差 |
| **树之间关系** | 彼此独立 | 后树专门学前树的错误 |
| **投票方式** | 平等投票 | 加权投票 |
| **训练速度** | 快（可并行） | 慢（必须串行） |
| **过拟合风险** | 较低（误差互相抵消） | 较高（串行累积可能记住噪音） |

**类比：**
- **Bagging** = 请100个专家各自独立判断，最后民主投票
- **Boosting** = 第1个专家先判断 → 第2个专家专门研究第1个判断错的案例 → 后辈专门补前辈短板

### 2. 为什么叫"梯度提升"？

GBDT 每棵树学习的"残差"，数学上就是 **MSE 损失函数的负梯度**：

$$
\text{残差} = y - \hat{y} = -\frac{\partial L}{\partial \hat{y}}
$$

所以 GBDT 本质上是在**函数空间**里做梯度下降：

| | 梯度下降 | GBDT |
|---|---------|------|
| **优化对象** | 参数 w | 预测值 ŷ |
| **更新公式** | w ← w - η·∇L | ŷ ← ŷ + η·(新树学的残差) |
| **本质** | 参数空间的梯度下降 | 函数空间的梯度下降 |

### 3. XGBoost 的三大改进

| 改进 | GBDT | XGBoost | 效果 |
|------|------|---------|------|
| **正则化** | 无 | Ω = γ·T + λ·Σw² | 惩罚树复杂度，防止过拟合 |
| **分割精度** | 一阶梯度 | 二阶梯度（曲率） | 更精确的最优分割点 |
| **速度** | 串行找分割点 | 特征并行搜索 | 快10倍+ |

**正则化机制：**
- γ 惩罚叶子数量（每分裂一次都要"交税"）
- λ 惩罚叶子权重过大（类似 L2，把极端预测往 0 拉）

### 4. 本次实验为何三者表现一致？

Iris 数据集太简单（150样本，4特征，3类线性可分），三种方法都轻松达到 100%。

**三者差异会在以下场景显现：**
- 数据量大（Boosting 更慢但可能更准）
- 特征多且有噪音（XGBoost 正则化优势明显）
- 类别不平衡（需要调整 `scale_pos_weight`）
- 容易过拟合的数据（RandomForest 更稳健）

## 失误签名复现

**"对象/参数搞反"** 在本次代码中复现3次：

1. ❌ `models.fit(...)` → ✅ `model.fit(...)`（循环变量搞混）
2. ❌ `accuracy_score(X_train, ...)` → ✅ `accuracy_score(y_train, ...)`（特征 vs 标签）
3. ❌ `model.predict(y_train)` → ✅ `model.predict(X_train)`（标签 vs 特征）

**自检药方：** 代入极端值 — `accuracy_score` 比较的是"真实标签 vs 预测标签"，都是 y 开头；`model.predict()` 吃的是特征 X。
